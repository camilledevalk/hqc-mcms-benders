# Julia Environments

## Prerequisites

- **Julia 1.10 (LTS)** — required for full gradient-based optimization support via Enzyme.jl.
  Install via [juliaup](https://github.com/JuliaLang/juliaup):
  ```bash
  curl -fsSL https://install.julialang.org | sh
  juliaup add lts
  juliaup default lts
  ```

## MPS-JuliQAOA

MPS-based QAOA simulation using [JuliQAOA.jl](https://github.com/lanl/JuliQAOA.jl) (mps branch)
with [ITensor](https://itensor.org/) Matrix Product State methods.

### Setup (first time)

```bash
cd julia/MPS_JuliQAOA
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

This reads `Project.toml` and resolves all dependencies into a local `Manifest.toml`.

### Running

```bash
# Interactive REPL
julia --project=julia/MPS_JuliQAOA

# Run a script
julia --project=julia/MPS_JuliQAOA scripts/my_script.jl
```

### HPC Usage

On an HPC cluster, the typical workflow is:

1. **Install Julia** on the cluster (or load the module):
   ```bash
   module load julia/1.10   # cluster-specific
   ```

2. **Instantiate the environment** (once, on a login node with internet):
   ```bash
   cd /path/to/logistiqs/julia/MPS_JuliQAOA
   julia --project=. -e 'using Pkg; Pkg.instantiate(); Pkg.precompile()'
   ```

3. **Submit jobs** referencing the project:
   ```bash
   julia --project=/path/to/logistiqs/julia/MPS_JuliQAOA my_job.jl
   ```

4. **Thread parallelism** — JuliQAOA/ITensor can use multiple threads:
   ```bash
   julia --project=julia/MPS_JuliQAOA --threads=auto my_job.jl
   ```

### Package Management

- **Add a package**: `julia --project=. -e 'using Pkg; Pkg.add("PackageName")'`
- **Update packages**: `julia --project=. -e 'using Pkg; Pkg.update()'`
- **Check status**: `julia --project=. -e 'using Pkg; Pkg.status()'`

Only `Project.toml` is committed to git. `Manifest.toml` is generated by `Pkg.instantiate()` and is gitignored to avoid platform-specific lock conflicts on HPC vs local.
